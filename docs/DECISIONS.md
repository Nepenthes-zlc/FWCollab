## D-0003：开发运行时保持项目本地隔离

- 日期：2026-09-10
- 状态：accepted
- 关联任务：P00-02

### 决策

使用校验过 SHA-256 的官方 `uv 0.12.12` Windows 发布包，在项目忽略目录 `.tools/` 中安装 CPython 3.11.16，并由 `uv.lock` 锁定项目依赖。虚拟环境位于 `.venv/`，二者都不进入版本控制或正式产物。

### 后果

开发机不需要修改系统 PATH；CI 和其他开发者仍可使用任意符合 Python 3.11+ 与锁文件的环境。工具二进制和 Python 分发包只是本机开发设施，不是 benchmark 证据。

## D-0009：用72个状态谓词DAG替代旧地图DAG

- 日期：2026-09-12
- 状态：accepted
- 关联任务：S04-03

### 决策

删除此前面向S01–S24手工维护的地图课程DAG和24张关内事件DAG，统一采用 `fwcollab.symbolic.state_dag.v1`。新目录基于30种一级元机关生成72个抽象状态依赖图，难度分布为L1–L6的4/8/12/16/18/14；L1/L2用于诊断，L3–L6用于正式规划评分。

节点使用受控 `predicate.op/motif/state` 表示可验证状态，自然语言只保存在展示字段。比较器分别提供纯拓扑和受控类型比较，忽略标题、摘要、节点ID、JSON顺序、坐标、phase具体数字及全局agent A/B换名。

### 后果

- 私有参考图保存于 `eval_private/dag_curriculum/`，不能注入游戏agent观测。
- agent候选图与参考图共用 `schemas/state_dag.schema.json`，可以独立读写、验证、渲染和比较。
- 72个DAG当前是空间落地前的抽象结构，不等同于72张可运行地图。
- 后续地图生成必须把DAG节点绑定到权威回放谓词，并验证无绕过、可解性和保持区间。

## D-0010：冻结公开规则 v3.1、结构化握手与二维核心图

- 日期：2026-09-13
- 状态：accepted
- 关联任务：S04-06、S04-07

### 决策

把 `fwcollab.symbol_rules.v3.1` 作为 agent、地图作者、runner 和评测器共享的公开规则版本。每轮 observation 公开紧凑机器规则；完整人类可读规则保存在 `docs/PUBLIC_RULEBOOK.md`。保留既有“回合前门态检查进入、移动后重算、已占据关闭执行器格仍可离开”的确定性语义，以免旧轨迹在无版本迁移的情况下失效。

公开消息增加 `stage/status/fact/request/until` 字段，并采用 `READY → HOLDING → CROSSED → RELEASE` 持续控制握手。字符串消息继续兼容旧轨迹，但新模型提示要求结构化消息。runner 附加发送轮、送达轮和依据状态哈希。

原 72 张 v3 直线控制网络明确降级为机关链诊断集。新增 12 张二维房间核心图：上下区域都有实际分支与纵向移动，控制器位于支路，持续控制执行器只阻断需要通过的队友，避免持板者被自己的门形成非预期自锁。

### 后果

- 旧模型成绩仍按当时提示和轨迹保留，不与新协议成绩直接合并。
- timeout 继续作为权威结果，但新轨迹附带 cycle、blocked、deadlock 或 budget 分类。
- 12 张二维核心图是下一轮地图设计基础，仍只覆盖 v3 控制器网络，不冒充完整 M01–M30 数据集。

## D-0011：模型输入去重、公开状态增量与可选 DAG 协商

- 日期：2026-09-13
- 状态：accepted
- 关联任务：S04-09

### 决策

公开规则升级为 `fwcollab.symbol_rules.v3.2`，不改变权威离散环境的动作或结算语义。模型每轮读取新的 `fwcollab.agent_observation.v1` 投影：保留完整动态/静态符号行和机关接线，删除逐墙坐标、带坐标字符串与行数组双份表示、v3 控制器/执行器的重复类型视图；新增明确的坐标增量、轮数预算、上一轮公开事件/双方反馈和最近 8 条已送达消息。

可旋转镜面公开 `initial/current/controlled_by`，规则书公开 `/` 与 `\` 的精确方向变换。无新协作信息时允许 `message=null`，持板握手从固定解题策略改为需要同步时的推荐协议，避免把单一计划作为必答提示泄露。

运行配置明确区分 `coordination_mode=emergent` 与 `protocol_assisted`：前者从模型规则投影中移除固定握手序列，后者公开推荐协议。两种模式共享同一环境语义，但属于不同提示条件，结果不得合并。

新增可选 `planning_rounds=2`：第一轮 F/W 独立生成公开 schema 合法的候选状态 DAG，第二轮互看候选并修订。runner 判断双方拓扑和受控类型共识，单独记录规划调用与错误；只有 agent 候选进入动作上下文，私有参考 DAG、见证和针对关卡的比较反馈仍严格隔离。默认值为 0，因此旧在线控制实验不会被悄悄改成不同任务。

### 兼容性

完整权威 observation 继续写入 trace，HTML 与重放器仍使用该表示。新镜面便利字段不参与既有状态哈希和地图指纹，旧 v3.1 轨迹可在 v3.2 代码下逐轮验证。旧 72 图真实模型成绩保留为 v3.1 输入基线，不与尚未重跑的 v3.2 结果混合。
