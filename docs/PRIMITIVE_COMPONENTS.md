# FWCollab 元组件与公开机制背景

状态：当前符号规则集 `fwcollab.symbol_rules.v3.2` 的元组件背景说明；v1/v2 地图保持兼容。

用途：统一地图作者、运行框架和两个游戏 agent 对元组件的理解。本文件可以作为公开机制背景提供给 agent，因为它只描述通用规则，不包含具体关卡的参考解、隐藏依赖 DAG、最优轨迹或评测标签。

权威性：本文件是便于阅读的机制目录；精确结算顺序、门格占据和通信协议见 `docs/PUBLIC_RULEBOOK.md`。出现歧义时，以 `SYMBOL_SPEC.md` 和 `src/fwcollab/symbolic/` 的解析、状态更新实现为准。

## 1. 任务模型

FWCollab 是一个双智能体离散合作规划环境：火娃 agent 控制 `F`，水娃 agent 控制 `W`。每轮双方基于同一份冻结观测各自选择 `UP`、`DOWN`、`LEFT`、`RIGHT` 或 `WAIT`，移动动作只能前进一个相邻格。两个动作共同结算后，环境更新机关状态，并在下一轮向双方提供完整的新观测。

本环境考察路线规划、行动顺序、持续支援、资源交接、通信和失败恢复，不考察跳跃、重力、速度、摩擦、连续碰撞或像素级操作。不要根据原版《森林冰火人》的连续物理规则推断本环境中未明确声明的行为。

### 1.1 静态层与动态层

观测包含两个互补表示：

- `map.terrain_rows/mechanisms`：静态布局和机关连接。角色站在某格上时，底层元组件仍可在这里查到。
- `map.current_rows`：当前动态画面。它显示门、拨杆、切换器、热相地块、传感器、镜面和桥的当前状态，但角色或可移动物体可能覆盖底层符号。
- `dynamic_state`：机关状态、角色位置、箱子位置和机关球位置等结构化数据。
- `clock/last_transition`：剩余轮数以及上一轮已经结算的公开变化。

agent 不能只依赖 `current_rows` 判断底层地形；应结合 `terrain_rows/mechanisms` 和 `dynamic_state` 阅读。权威回放文件仍保留旧的完整字段名，供审计和渲染使用。

### 1.2 符号状态不是新元组件

以下变化表示同一元组件的不同状态：

| 静态/关闭符号 | 动态/激活符号 | 含义 |
|---|---|---|
| `A`–`E` | `a`–`e` | 门关闭 / 门打开 |
| `L` | `l` | 持久拨杆未激活 / 已激活 |
| `T` | `t` | 切换器关闭 / 开启 |
| `S` | `s` | 光传感器未点亮 / 已点亮 |
| `=` | `-` | 离散桥收起 / 展开 |
| `I` | `~` | 热相地块冻结 / 液态 |
| `M` | `/` 或 `\` | 可旋转镜面的当前朝向 |

因此，当前实现包含 19 种机关元组件，而不是把每个动态符号都算作一种新组件。

## 2. 元组件分类总览

当前目录采用 9 个概念大类。其中 8 类已有实现，“物理转换器”是为后续设计保留的空类。

| 大类 | 已实现的元组件 | 数量 | 主要作用 |
|---|---|---:|---|
| 触发器 Trigger | 压力板、持久拨杆、二态切换器、光传感器 | 4 | 产生控制状态 |
| 信号源 Source | 光源 | 1 | 产生持续信号 |
| 路由器 Router | 固定镜面、可旋转镜面 | 2 | 改变信号传播方向 |
| 通行执行器与约束 | 普通门、离散桥、单向门 | 3 | 改变或限制可达性 |
| 可移动资源 | 箱子、机关球 | 2 | 搬运、占板、遮光和空间阻塞 |
| 物理转换器 | 当前未实现 | 0 | 预留给离散配重、跷跷板等机制 |
| 地形与状态场 | 水池、熔岩、通用危险区、热相地块 | 4 | 产生角色差异和环境状态 |
| 状态改变器 | 加热器、冻结器 | 2 | 改变热相地块状态 |
| 空间转换器 | 配对传送门 | 1 | 改变角色或物体的位置 |

合计：19 种已实现的机关元组件。

## 3. 触发器

### 3.1 压力板 `1`–`9`

**角色：**保持型触发器。

**声明示例：**

```text
@plate 1 opens A accepts F,W
@plate 2 opens B accepts O
```

**规则：**

- 压力板只有在被允许的负载持续占据时才激活，负载离开后立即失效。
- `accepts F`、`accepts W` 分别允许火娃和水娃触发。
- `accepts O` 允许重物触发；当前箱子 `O` 和机关球 `o` 都按 `O` 类负载处理。
- 激活的压力板可以打开声明中的门。
- 离散桥也可以通过 `@platform = controlled_by 1` 引用某块压力板。
- 数字是线路标识，不表示压力大小或触发顺序。

**规划特性：**压力板可以要求一名角色持续留守，也可以先把箱子或机关球送上去替代角色，从而形成支援、交接和资源分配问题。

### 3.2 持久拨杆 `L/l`

**角色：**一次开启、持续保持的触发器。

**声明示例：**

```text
@lever L opens A
```

**规则：**

- 角色进入 `L` 所在格后，拨杆激活并在动态图中显示为 `l`。
- 激活后即使角色离开，状态也不会恢复。
- 当前拨杆只能从关闭变为开启，不能再次关闭。
- 拨杆可以打开门；离散桥也可以通过 `controlled_by L` 使用它。
- 箱子和机关球经过或停在 `L` 上都不会触发拨杆。

**规划特性：**拨杆适合表达不可撤销的解锁步骤，以及“先绕路开锁，再返回主路线”的依赖。

### 3.3 二态切换器 `T/t`

**角色：**可逆、锁存型触发器。

**声明示例：**

```text
@toggle T toggles A,M
```

**规则：**

- 角色每次从其他格进入切换器时翻转一次状态：`T → t` 或 `t → T`。
- 角色停留在切换器上不会每轮重复翻转；必须先离开再重新进入。
- 当前切换器可以切换门 `A`–`E` 和可旋转镜面 `M`。
- 离散桥可以另外通过 `controlled_by T` 读取切换器状态。
- 箱子和机关球不能触发切换器。
- 两名角色在同一轮进入同一个切换器时，整轮只翻转一次。

**规划特性：**切换器会产生可逆状态空间，要求 agent 记住当前状态，并考虑再次切换是否会破坏队友已经依赖的通路。

### 3.4 光传感器 `S/s`

**角色：**由光路驱动的持续型触发器。

**声明示例：**

```text
@light + direction RIGHT sensor S opens A
```

**规则：**

- 光线到达传感器时，动态图显示 `s`，关联门保持开启。
- 光线被截断或改向后无法到达传感器时，显示恢复为 `S`，关联门关闭。
- 光传感器当前只能直接控制门，不能直接控制离散桥。
- 传感器状态由当前光路重新计算，不是永久锁存状态。

**规划特性：**光传感器把物体摆放、镜面朝向和通路状态连接起来，适合形成多步条件依赖。

## 4. 信号源

### 4.1 光源 `+`

**角色：**持续信号源。

**声明示例：**

```text
@light + direction UP sensor S opens B
```

**规则：**

- 光源持续沿 `UP`、`DOWN`、`LEFT` 或 `RIGHT` 中声明的方向发射光线。
- 光源不需要角色开启，也没有开关状态。
- 光线被墙 `#`、箱子 `O` 或机关球 `o` 阻断。
- 光线遇到镜面会改变方向；到达目标传感器 `S` 后点亮传感器。
- 当前实现中的门不会阻挡光线；只有明确列出的阻光物体会阻断光路。

**规划特性：**光源本身通常不是操作目标，它与镜面、可移动遮光物和传感器共同构成光路子系统。

## 5. 信号路由器

### 5.1 固定镜面 `/` 与 `\`

**角色：**无状态光线路由器。

**规则：**

- `/` 和 `\` 按各自几何方向反射光线。
- 镜面朝向固定，角色不能旋转或搬动它。
- 固定镜面只有在地图声明了光路时才允许出现。
- 角色可以进入镜面所在格；镜面不构成墙。

反射关系：

| 入射方向 | `/` 的出射方向 | `\` 的出射方向 |
|---|---|---|
| `UP` | `RIGHT` | `LEFT` |
| `DOWN` | `LEFT` | `RIGHT` |
| `LEFT` | `DOWN` | `UP` |
| `RIGHT` | `UP` | `DOWN` |

### 5.2 可旋转镜面 `M`

**角色：**具有两个离散朝向的光线路由器。

**声明示例：**

```text
@mirror M initial slash
@toggle T toggles M
```

**规则：**

- 初始朝向为 `slash` 或 `backslash`，分别对应 `/` 或 `\`。
- 切换器 `T` 激活时，镜面切换到另一种朝向；`T` 恢复时，镜面恢复对应朝向。
- 静态布局中该组件仍是 `M`，动态地图显示当前实际的 `/` 或 `\`。
- 当前可旋转镜面必须由切换器控制，角色不能直接与镜面交互。

**规划特性：**调整镜面可能同时改变光传感器和门的状态，因此需要在移动前后重新确认光路。

## 6. 通行执行器与约束

### 6.1 普通门 `A`–`E` / `a`–`e`

**角色：**二态通行执行器。

**规则：**

- 大写 `A`–`E` 表示关闭；对应小写 `a`–`e` 表示打开。
- 关闭门阻挡角色、箱子和机关球；打开后可以双向通过。
- 门可以由压力板、持久拨杆、二态切换器或光传感器控制。
- 同一扇门有多个控制来源时，当前采用 OR 语义：任意一个来源有效，门就打开。
- 每扇出现在地图中的门都必须至少关联一个合法控制器。

**规划特性：**普通门表达“满足条件后获得通路”；保持型控制器还会产生通过窗口和队友支援问题。

### 6.2 离散桥 `=` / `-`

**内部名称：**代码和地图指令中使用 `platform`，在机制说明中称为离散桥或离散移动桥。

**声明示例：**

```text
@platform = controlled_by 1
```

**规则：**

- `=` 表示收起或不可用，角色和可移动物体不能进入。
- `-` 表示展开，作为普通可通行格处理。
- 控制器可以是压力板 `1`–`9`、拨杆 `L` 或切换器 `T`。
- 桥只有“不可通行/可通行”两个离散状态，不模拟移动速度、载具运动、承重、坠落或连续动画。

**规划特性：**压力板控制的桥特别适合“一个角色维持桥面，另一个角色先通过”的协作结构。

### 6.3 单向门 `J`

**角色：**静态方向约束，不是普通开关门。

**声明示例：**

```text
@oneway J allows RIGHT
```

**规则：**

- 只有以声明的动作方向进入 `J` 才合法。例如 `RIGHT` 表示从左侧向右进入。
- 方向限制只检查“进入门格”的动作；站在 `J` 上以后，可以向任意方向离开。
- 当前单向门没有打开/关闭状态，也不连接其他触发器。
- 角色、箱子和机关球进入时都受相同的方向限制。

**规划特性：**单向门用于制造路线承诺、限制返回和资源放置顺序。穿过前应确认不再需要返回取物或帮助队友。

## 7. 可移动资源

### 7.1 箱子 `O`

**角色：**可精确摆放的离散重物。

**规则：**

- 角色向箱子移动时尝试把箱子沿同一方向推动一格。
- 箱子只能推，不能拉。
- 目标格被墙、关闭门、收起的桥、错误方向的单向门、危险区、出口、角色或其他可移动物体占据时，推动失败。
- 箱子可以压住接受 `O` 的压力板。
- 箱子进入配对传送门后立即出现在另一端。
- 箱子会阻断光线，因此也可以作为可移动遮光物。
- 箱子停在拨杆、切换器、加热器或冻结器上不会触发这些组件。

**规划特性：**箱子移动精确、状态稳定，适合永久替代角色占板，但错误推进墙角后可能无法恢复。

### 7.2 滚动机关球 `o`

**角色：**需要几何截停的离散重物。

**规则：**

- 角色推动一次后，机关球沿该方向连续滚动，直到下一个障碍之前才停止。
- 机关球最终停在接受 `O` 的压力板上时可以持续触发；只是滚过压力板不算占据。
- 机关球可以进入配对传送门，并在出口处保持原来的滚动方向继续前进。
- 机关球与箱子一样会阻断光线。
- 机关球不能被拉动，也不能由角色在滚动途中主动停止。
- 墙、关闭门、收起的桥、错误方向的单向门、危险区、出口、角色和其他可移动物体都可以形成阻挡。

**规划特性：**机关球的难点不是逐格运输，而是选择推动方向、安排截停障碍并让最终停点与压力板或光路对齐。

## 8. 物理转换器（预留，当前未实现）

该类计划容纳“输入一种离散负载关系，输出另一种空间或通行状态”的组件，例如离散跷跷板、配重台或多位置升降台。当前规则集没有对应符号、解析指令或状态更新逻辑。

在真正实现并测试之前：

- 不得把跷跷板、配重、重力平台等写入可运行地图；
- 不得让 agent 假设箱子有质量差异或角色有重量差异；
- 不得把原版连续物理行为当成当前公开规则。

## 9. 地形与状态场

### 9.1 水池 `~`

- 水娃进入后安全。
- 火娃进入后死亡，团队任务立即失败。
- 箱子和机关球不能进入。

### 9.2 熔岩 `^`

- 火娃进入后安全。
- 水娃进入后死亡，团队任务立即失败。
- 箱子和机关球不能进入。

### 9.3 通用危险区 `x`

- 火娃或水娃进入都会死亡并导致团队失败。
- 箱子和机关球不能进入。

### 9.4 热相地块 `I` / `~`

**声明示例：**

```text
@thermal I initial frozen heater H freezer K
```

**规则：**

- 冻结状态显示为 `I`，火娃和水娃都可以安全通过。
- 液态状态显示为 `~`，按水池处理：水娃安全，火娃进入会死亡。
- `initial frozen` 或 `initial liquid` 声明初始状态。
- 当前一张地图内的所有 `I` 共享同一个热相状态，而不是分别变化。
- 状态由加热器 `H` 和冻结器 `K` 持久改变。
- 不模拟冰面摩擦、滑行、融化时间或温度数值。

**规划特性：**热相地块用于改变角色可达性。冻结可能帮助火娃通过，而液态仍允许水娃通行。

## 10. 状态改变器

### 10.1 加热器 `H`

- 角色从其他格进入 `H` 时，将全部热相地块持久设为液态。
- 角色离开后不会自动恢复。
- 箱子和机关球不能触发。
- 加热器不伤害角色，也不产生连续温度变化。

### 10.2 冻结器 `K`

- 角色从其他格进入 `K` 时，将全部热相地块持久设为冻结状态。
- 角色离开后不会自动恢复。
- 箱子和机关球不能触发。
- 如果两名角色在同一轮分别进入 `H` 和 `K`，环境报告热控制冲突，并保持原热相状态不变。

## 11. 空间转换器

### 11.1 配对传送门 `P`、`Q`、`R`

**声明示例：**

```text
@portal P
```

**规则：**

- 每个被声明的传送门字母必须在地图中恰好出现两次。
- 角色或被推动物体进入一端后，立即出现在同字母的另一端。
- 一次进入只传送一次，不会在同一个微步中来回弹跳。
- 箱子和机关球都可以传送；机关球在出口保持原滚动方向。
- 出口被箱子或机关球占据时，进入失败。
- `P`、`Q`、`R` 表示三套彼此独立的配对线路，不表示目的地优先级。

**规划特性：**传送门改变地图的邻接关系，可以缩短路线、跨越隔离区，也可能把资源送入难以回收的位置。

## 12. 基础地图元素

这些元素构成任务和地图，但不计入 19 种机关元组件。

| 符号 | 名称 | 规则 |
|---|---|---|
| `#` | 墙 | 不可进入，并阻断光线 |
| `.` | 普通地面 | 无附加效果，可正常进入 |
| `F` | 火娃初始位置 | 由火娃 agent 控制 |
| `W` | 水娃初始位置 | 由水娃 agent 控制 |
| `f` | 火娃出口 | 只有火娃可以进入 |
| `w` | 水娃出口 | 只有水娃可以进入 |

任意角色进入对方的出口都会被阻挡。只有当火娃当前位于 `f`、水娃当前位于 `w` 时，团队才成功。先到达出口的一方仍保留在环境状态中，可以等待，也可以再次离开。

## 13. 控制关系兼容表

下表描述当前已经实现的直接控制关系，不代表未来扩展能力。

| 控制源 | 门 | 离散桥 | 可旋转镜面 | 热相地块 |
|---|---:|---:|---:|---:|
| 压力板 `1`–`9` | 是 | 是 | 否 | 否 |
| 持久拨杆 `L/l` | 是 | 是 | 否 | 否 |
| 二态切换器 `T/t` | 是 | 是 | 是 | 否 |
| 光传感器 `S/s` | 是 | 否 | 否 | 否 |
| 加热器 `H` | 否 | 否 | 否 | 设为液态 |
| 冻结器 `K` | 否 | 否 | 否 | 设为冻结 |

典型组合链为：

```text
角色/重物 → 压力板 → 门或离散桥
角色 → 持久拨杆 → 门或离散桥
角色 → 二态切换器 → 门、离散桥或可旋转镜面
光源 → 镜面/遮光物 → 光传感器 → 门
角色 → 加热器/冻结器 → 热相地块 → 角色可达性变化
角色/箱子/机关球 → 传送门 → 空间位置变化
```

## 14. 当前实现边界

以下是 `v2` 当前实现限制，不应被误解为元组件的一般理论限制：

- 门标识限定为 `A`–`E`，压力板标识限定为 `1`–`9`，传送门标识限定为 `P`–`R`。
- 每张地图当前最多声明一条切换器规则、一条单向门规则、一套热相规则、一条光路规则、一条可旋转镜面规则和一条离散桥规则。
- 一张地图中的所有 `I` 共享状态；所有 `=` 共享同一桥状态。
- 当前只有角色进入会触发 `L`、`T`、`H`、`K`；箱子和机关球不会触发它们。
- 压力板把箱子和机关球统一视为 `O` 类负载，尚不能在 `accepts` 中区分两者。
- 光传感器只能直接开门；光源方向固定；可旋转镜面只能由 `T` 控制。
- 单向门只有方向约束，没有额外开关状态。
- 不存在显式 `INTERACT` 动作；所有机关通过进入、占据、推动、光照或当前状态自动结算。
- 不实现连续物理、重量数值、箱子堆叠、拉动物体、跳跃、重力、摩擦和滑行。

## 15. 给 agent 的阅读原则

当本文件作为 agent 背景提供时，agent 应遵循以下原则：

1. 每轮重新读取更新后的 `map_rows`、`terrain_rows/layout` 和 `state`，不要假设机关状态没有变化。
2. 区分保持型、持久型和可逆型触发器：压力板需要持续占据，拨杆持久开启，切换器每次重新进入都会翻转。
3. 计划推动箱子前检查其下一格；计划推动机关球前检查整条滚动线路和最终截停位置。
4. 穿过单向门或使用传送门前考虑资源和队友是否仍需返回。
5. 不把动态小写符号误认为新机关，也不因角色覆盖地图格而忽略底层机关。
6. 不假设未写入公开规则的原版游戏物理、隐藏按钮、自动寻路或批量移动能力。

## 16. 从元组件组合为元机关

### 16.1 “元组件”与“元机关”的区别

- **元组件（primitive component）**是规则系统中的最小构件，例如压力板、门、箱子或水池。
- **元机关（mechanism motif）**是可以独立放入关卡、具有明确输入—状态—效果语义的最小玩法单元。
- **复合机关（compound mechanism）**由两个或更多元机关串联、并联或嵌套形成，例如“箱子穿过传送门后压住压力板，展开桥让队友去旋转镜面”。

有些元组件本身已经具有完整规则，因此单独就是一个元机关，例如普通地面、水池、箱子、机关球和单向门。有些元组件只有与其他组件连接才产生完整效果，例如压力板必须连接门或桥，光传感器必须位于“光源—传感器—门”链中。

如果允许任意数量的元组件重复，并允许元机关继续串联，可能的复合机关数量没有有限上界。因此下面统计的是**规范化一级元机关**，而不是所有可能关卡。

### 16.2 计数约定

为了让数量可复现，本目录采用以下规则：

1. 只统计当前 `v2` 规则真实支持的组合，不统计未来设想。
2. 一个元机关必须是独立可理解的最小规则单元；组合中每个列出的组件都承担必要作用。
3. 符号 ID 不另算类型，例如门 `A` 和门 `B` 都属于普通门机关。
4. 方向、初始状态和朝向不另算类型，例如四种单向门方向仍算一种元机关。
5. 火娃限定、水娃限定或双方均可触发属于压力板参数，不分别计数。
6. `/` 与 `\` 是固定镜面的朝向，不分别计数。
7. 多门、多压板、多镜面及多个相同组件的重复不另算；这些属于同一种元机关的规模变化。
8. 箱子和机关球造成不同的操作与规划过程，因此在“负载压板”和“移动遮光”中分别计为不同元机关。
9. 一个光学元机关最多包含一种路由方式和一种可选遮光资源；更长的镜面链或多资源光路归入复合机关。
10. 出生标记 `F/W` 是智能体，不是机关；专属出口 `f/w` 共同构成一种团队目标机关。

按照上述约定，当前可得到 **30 种规范化一级元机关**：

```text
10 种原子/单体机关
+ 10 种通行控制机关
+  9 种光学机关
+  1 种热相机关
= 30 种一级元机关
```

### 16.3 A 类：原子或单体机关（10种）

这类机关不需要连接另一个控制组件就能表达完整的局部规则。传送门虽然需要两个端点，出口虽然需要火/水两个目标，但它们分别属于一个组件模板的内在结构，因此各计为一种。

| ID | 元机关 | 必要符号 | 完整语义 |
|---|---|---|---|
| `M01` | 普通地面 | `.` | 可进入、无附加效果的基础通行格 |
| `M02` | 墙体阻挡 | `#` | 阻止角色和物体进入，同时阻断光线 |
| `M03` | 水池差异地形 | `~` | 水娃安全，火娃进入失败 |
| `M04` | 熔岩差异地形 | `^` | 火娃安全，水娃进入失败 |
| `M05` | 通用危险地形 | `x` | 任一角色进入都会导致团队失败 |
| `M06` | 可推箱子 | `O` | 每次被推一格，可稳定停放、占板或遮光 |
| `M07` | 滚动机关球 | `o` | 被推后滚到障碍前，可占板或遮光 |
| `M08` | 单向通行 | `J` | 仅允许从声明方向进入，离开方向不限 |
| `M09` | 配对传送 | `P`、`Q` 或 `R` 的一对端点 | 角色和可移动物体从一端立即到达另一端 |
| `M10` | 双角色专属出口 | `f`、`w` | 双方分别到达自己的出口时团队成功 |

说明：`F/W` 只标识控制主体的初始位置，不作为额外元机关计数；`f/w` 的目标判定具有独立规则，因此计为 `M10`。

### 16.4 B 类：通行控制机关（10种）

这一类由“触发方式 + 通行执行器”构成。普通门和离散桥是两种执行器；压力板、拨杆和切换器是三种直接控制方式。压力板还按实际负载分为角色、箱子和机关球三种操作形态。

| ID | 元机关 | 最小组件结构 | 状态语义 |
|---|---|---|---|
| `M11` | 角色压板门 | 角色 → `1`–`9` → `A`–`E` | 角色持续占板时门打开 |
| `M12` | 箱子压板门 | `O` → `1`–`9` → `A`–`E` | 箱子停在压板上时门打开 |
| `M13` | 机关球压板门 | `o` → `1`–`9` → `A`–`E` | 机关球最终停在压板上时门打开 |
| `M14` | 角色压板桥 | 角色 → `1`–`9` → `=`/`-` | 角色持续占板时桥展开 |
| `M15` | 箱子压板桥 | `O` → `1`–`9` → `=`/`-` | 箱子停在压板上时桥展开 |
| `M16` | 机关球压板桥 | `o` → `1`–`9` → `=`/`-` | 机关球最终停在压板上时桥展开 |
| `M17` | 持久拨杆门 | `L/l` → `A`–`E` | 角色触发一次后门永久打开 |
| `M18` | 持久拨杆桥 | `L/l` → `=`/`-` | 角色触发一次后桥永久展开 |
| `M19` | 二态切换门 | `T/t` → `A`–`E` | 每次重新进入切换器都翻转门状态 |
| `M20` | 二态切换桥 | `T/t` → `=`/`-` | 每次重新进入切换器都翻转桥状态 |

通行控制机关的组合公式是：

```text
压力板：3种负载方式 × 2种执行器 = 6种
拨杆：  1种触发方式 × 2种执行器 = 2种
切换器：1种触发方式 × 2种执行器 = 2种
合计：6 + 2 + 2 = 10种
```

以下差异只作为参数，不增加类型数量：

- 压力板接受 `F`、`W`、`F,W` 或同时接受 `O`；
- 一个触发器连接门 `A` 还是门 `B`；
- 一个控制器控制一格还是多格同状态桥面；
- 同一机关中门或桥的空间位置和路径长度。

### 16.5 C 类：光学机关（9种）

一个能产生通行效果的完整光学机关至少需要：

```text
光源 `+` → 可选路由器 → 光传感器 `S/s` → 门 `A`–`E`
```

当前有三种路由方式：无镜面直射、固定镜面、切换器控制的可旋转镜面；还有三种遮光方式：无遮挡、箱子遮光、机关球遮光。两者组合得到 9 种。

| ID | 元机关 | 最小组件结构 | 主要规划操作 |
|---|---|---|---|
| `M21` | 直射光感门 | `+` → `S/s` → 门 | 保持直接光路连通 |
| `M22` | 箱子遮光门 | `+` → `O` → `S/s` → 门 | 推开或移入箱子以改变光路 |
| `M23` | 机关球遮光门 | `+` → `o` → `S/s` → 门 | 计算滚动终点以改变光路 |
| `M24` | 固定反射光感门 | `+` → `/`或`\` → `S/s` → 门 | 利用固定几何反射建立光路 |
| `M25` | 固定反射箱子遮光门 | `+` → 固定镜面 + `O` → `S/s` → 门 | 同时考虑反射路径和箱子位置 |
| `M26` | 固定反射机关球遮光门 | `+` → 固定镜面 + `o` → `S/s` → 门 | 同时考虑反射路径和球的截停位置 |
| `M27` | 可旋转反射光感门 | `T/t` → `M`；`+` → `M` → `S/s` → 门 | 切换镜面方向以接通光路 |
| `M28` | 可旋转反射箱子遮光门 | `T/t`、`M`、`+`、`O`、`S/s`、门 | 协调镜面状态与箱子遮光状态 |
| `M29` | 可旋转反射机关球遮光门 | `T/t`、`M`、`+`、`o`、`S/s`、门 | 协调镜面状态与球的滚动终点 |

光学机关的组合公式是：

```text
3种路由方式（直射、固定镜面、可旋转镜面）
× 3种遮光方式（无、箱子、机关球）
= 9种
```

这里的“箱子遮光”和“机关球遮光”包括两种相反目标：把遮光物移出光路以点亮传感器，或把遮光物移入光路以熄灭传感器。二者使用同一状态关系，因此不重复计数。

### 16.6 D 类：热相机关（1种）

| ID | 元机关 | 最小组件结构 | 状态语义 |
|---|---|---|---|
| `M30` | 冻结—融化热相系统 | `H` + `K` → `I/~` | `H` 设为液态，`K` 设为冻结；状态持续保持 |

当前解析格式要求一套热相规则同时声明 `I`、`H` 和 `K`，因此把它计为一个可逆热相元机关，而不是分别计为“加热机关”和“冻结机关”。初始为 `frozen` 还是 `liquid` 是参数，不增加类型数量。

### 16.7 尚未单独计数的合法交互

下列交互已经被环境支持，但在一级目录中作为已有元机关的通用能力或复合方式，不额外增加编号：

- 箱子或机关球穿过传送门：属于 `M06/M07` 与 `M09` 的复合。
- 箱子或机关球通过单向门：属于 `M06/M07` 与 `M08` 的复合。
- 箱子穿过传送门后压板开门：属于传送、移动资源和压板门三个元机关的串联。
- 一个切换器同时控制门和可旋转镜面：属于切换门与旋转光路的共享控制器复合。
- 一个压力板同时开门和展开桥：属于两个通行控制元机关共享触发器。
- 多个控制器共同连接一扇门：属于控制机关的并联；当前门按 OR 语义开启。
- 多块固定镜面组成长光路：属于 `M24` 的规模扩展，不按镜面数量生成新类型。
- 危险地形与门、桥、传送门或单向门组合：属于地形机关与通行/空间机关的空间嵌套。

### 16.8 数量结论与扩展规则

在当前规则和上述一级计数约定下：

| 层级 | 数量 | 是否有限 | 用途 |
|---|---:|---:|---|
| 已实现元组件 | 19 | 是 | 构造规则的原子词汇，不含基础地面/墙/出口 |
| 规范化一级元机关 | 30 | 是 | 地图生成器和课程设计可直接使用的最小玩法模板 |
| 参数化实例 | 很多 | 在当前有限参数域内有限 | 改变 ID、方向、初态、接受角色、位置和长度 |
| 复合机关 | 无固定上限 | 否 | 通过串联、并联、分叉、汇合和共享组件构造完整关卡 |

后续新增元组件时，应按以下步骤维护数量：

1. 先判断它能否单独构成完整局部规则；能则加入 A 类。
2. 若它是触发器、路由器或执行器，则更新控制兼容表。
3. 只为产生不同状态转移或不同规划操作的组合增加元机关编号。
4. 仅改变符号 ID、方向、初态或重复数量时，不增加元机关类型。
5. 多个一级元机关的连接应记录为复合机关拓扑，不继续膨胀一级目录。

基于这30种一级元机关构建的72个L1–L6状态依赖DAG已经采用统一的可读写JSON格式生成。DAG数量、谓词节点、去重标准、agent候选图和比较协议见 `docs/STATE_DAG_CURRICULUM.md`；私有参考图不得作为游戏agent的背景信息注入。
